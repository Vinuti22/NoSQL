# Лабораторная работа №4: Агрегация данных, индексы и анализ производительности запросов MongoDB

**Тема:** Агрегация данных, индексы и анализ производительности запросов в MongoDB

**Инструменты:** MongoDB, mongosh / MongoDB Compass

## 1. Цель работы

Получить практические навыки построения **Aggregation Pipeline**, создания простых и составных индексов, анализа планов выполнения запросов с помощью метода `explain("executionStats")`, а также обоснованной оптимизации MongoDB-запросов на основе измеряемых показателей производительности.

После выполнения работы приобретаются навыки:

* Использования этапов `$match`, `$project`, `$group`, `$sort`, `$limit`, `$unwind` и `$lookup`.

* Создания простых и составных индексов.

* Понимания и анализа различий между сканированием всей коллекции (`COLLSCAN`) и сканированием индекса (`IXSCAN`).

* Чтения метрик `totalDocsExamined`, `totalKeysExamined` и `executionTimeMillis`.

* Построения оптимальных составных индексов с учетом принципа **ESR** (Equality, Sort, Range).

## 4. Выполнение практических заданий (Aggregation Pipeline)

В ходе работы создано и выполнено **10 конвейеров агрегации (Aggregation Pipeline)**.

### Задание 1. Фильтрация с `$match` (3 запроса)

#### Запрос 1.1: Фильтрация по строковому полю

Фильтрация товаров, относящихся к категории `"Accessories"`.

```
db.products.aggregate([
  { $match: { category: "Accessories" } }
]);

```

#### Запрос 1.2: Фильтрация по диапазону числовых значений

Поиск товаров с ценой от `100 000` до `300 000` ₸.

```
db.products.aggregate([
  { $match: { price: { $gte: 100000, $lte: 300000 } } }
]);

```

#### Запрос 1.3: Фильтрация по нескольким условиям и логическим операторам `$or` / `$in`

Выборка товаров категорий `"Notebook"` или `"Smartphone"` с рейтингом не ниже `4.7`.

```
db.products.aggregate([
  { 
    $match: { 
      category: { $in: ["Notebook", "Smartphone"] },
      rating: { $gte: 4.7 }
    } 
  }
]);

```

### Задание 2. Формирование результата с `$project` (2 запроса)

#### Запрос 2.1: Проекция выборочных полей

Вывод названия, категории и цены товара без служебного поля `_id`.

```
db.products.aggregate([
  { $match: { category: "Audio" } },
  { $project: { _id: 0, name: 1, category: 1, price: 1 } }
]);

```

#### Запрос 2.2: Создание вычисляемого поля

Расчет суммарной стоимости товара на складе (`inventoryValue = price * stock`).

```
db.products.aggregate([
  {
    $project: {
      _id: 0,
      name: 1,
      price: 1,
      stock: 1,
      inventoryValue: { $multiply: ["$price", "$stock"] }
    }
  }
]);

```

### Задание 3. Группировка с `$group` (2 запроса)

#### Запрос 3.1: Расчет агрегированных показателей по категориям

Группировка товаров по категориям с подсчетом количества, средней цены, минимальной и максимальной стоимости.

```
db.products.aggregate([
  {
    $group: {
      _id: "$category",
      totalProducts: { $sum: 1 },
      avgPrice: { $avg: "$price" },
      minPrice: { $min: "$price" },
      maxPrice: { $max: "$price" }
    }
  }
]);

```

#### Запрос 3.2: Агрегация суммарного запаса и среднего рейтинга

```
db.products.aggregate([
  {
    $group: {
      _id: "$category",
      totalStock: { $sum: "$stock" },
      avgRating: { $avg: "$rating" }
    }
  }
]);

```

### Задание 4. Сортировка и ограничение результата (`$sort`, `$limit`)

#### Запрос 4.1: ТОР-5 самых дорогих товаров в наличии

> **Объяснение сортировки:** Значение `1` задает сортировку по возрастанию, `-1` — по убыванию.

```
db.products.aggregate([
  { $match: { stock: { $gt: 0 } } },
  { $sort: { price: -1 } },
  { $limit: 5 },
  { $project: { _id: 0, name: 1, price: 1, stock: 1 } }
]);

```

### Задание 5. Работа с массивами через `$unwind`

#### Запрос 5.1: Разворачивание тегов и подсчет популярных тегов

Оператор `$unwind` дублирует документ для каждого элемента массива `tags`, позволяя сгруппировать данные по отдельным тегам.

```
db.products.aggregate([
  { $unwind: "$tags" },
  { $group: { _id: "$tags", count: { $sum: 1 } } },
  { $sort: { count: -1 } }
]);

```

### Задание 6. Объединение коллекций через `$lookup`

#### Запрос 6.1: Соединение заказов с покупателями

Объединение коллекции `orders` с информацией из `customers`.

* `from: "customers"` — целевая коллекция для внешнего соединения.

* `localField: "customerId"` — поле связи в исходной коллекции (`orders`).

* `foreignField: "customerId"` — поле связи в целевой коллекции (`customers`).

* `as: "customer"` — имя создаваемого массива с найденными совпадениями.

```
db.orders.aggregate([
  {
    $lookup: {
      from: "customers",
      localField: "customerId",
      foreignField: "customerId",
      as: "customer"
    }
  },
  { $unwind: "$customer" },
  {
    $project: {
      _id: 0,
      orderId: 1,
      total: 1,
      status: 1,
      "customer.name": 1,
      "customer.city": 1
    }
  }
]);

```

### Задание 7. Многоэтапный Aggregation Pipeline (4+ этапа)

#### Запрос 7.1: Анализ дорогих категорий с фильтрацией и ограничением

Конвейер из 5 этапов: фильтрация имеющихся товаров ➔ группировка ➔ фильтрация категорий со средней ценой > 100k ➔ сортировка ➔ выборка первых 3 категорий.

```
db.products.aggregate([
  { $match: { stock: { $gt: 0 } } },
  {
    $group: {
      _id: "$category",
      avgPrice: { $avg: "$price" },
      totalQuantity: { $sum: "$stock" }
    }
  },
  { $match: { avgPrice: { $gt: 100000 } } },
  { $sort: { avgPrice: -1 } },
  { $limit: 3 }
]);

```

## 5. Создание индексов и эксперименты с производительностью

Было проведено **4 эксперимента** по анализу планов выполнения запросов (`explain("executionStats")`).

### Эксперимент 1. Анализ запроса без индекса (COLLSCAN)

Запрос фильтрации товаров по категории:

```
db.products.find({ category: "Notebook" }).explain("executionStats");

```

* **План выполнения (`stage`):** `COLLSCAN` (полное сканирование коллекции).

* **Специфика:** СУБД была вынуждена просмотреть все 30 документов базы для поиска 3 совпадений.

### Эксперимент 2. Создание простого индекса

Создание однополевого индекса по полю `category`:

```
db.products.createIndex({ category: 1 });

```

Повторный запуск проверки:

```
db.products.find({ category: "Notebook" }).explain("executionStats");

```

* **План выполнения (`stage`):** `IXSCAN` (сканирование индекса) с последующим `FETCH`.

* **Результат:** Количество просмотренных документов (`totalDocsExamined`) сократилось с 30 до 3.

### Эксперимент 3. Составной индекс и устранение стадии SORT

Частый бизнес-сценарий: поиск товаров категории с сортировкой по цене:

```
db.products.find({ category: "Notebook" }).sort({ price: 1 });

```

Создание составного индекса:

```
db.products.createIndex({ category: 1, price: 1 });

```

Проверка плана выполнения:

```
db.products.find({ category: "Notebook" }).sort({ price: 1 }).explain("executionStats");

```

* **Результат:** В плане выполнения отсутствует отдельный шаг `SORT` (сортировка выполнена на уровне B-дерева индекса, так как ключи уже упорядочены).

### Эксперимент 4. Эксперимент с порядком полей по принципу ESR

Принцип **ESR (Equality, Sort, Range)** определяет правильный порядок полей в составном индексе:

1. **E** (Equality) — поля точного равенства.

2. **S** (Sort) — поля, по которым выполняется сортировка.

3. **R** (Range) — поля диапазонов (`$gte`, `$lte`, `$gt`, `$lt`).

Рассматривается запрос:

```
db.products.find({ category: "Accessories", rating: { $gte: 4.5 } }).sort({ price: 1 });

```

Сравнение двух составных индексов:

1. **Индекс А (соответствует ESR):** `{ category: 1, price: 1, rating: 1 }`

    * *Equality:* `category`

    * *Sort:* `price`

    * *Range:* `rating`

2. **Индекс Б (нарушает ESR):** `{ category: 1, rating: 1, price: 1 }`

**Анализ результатов:**

* При использовании **Индекса Б** база данных находит записи по равенству и диапазону, но вынуждена выполнять дополнительную операцию сортировки в оперативной памяти (`SORT` stage), так как диапазон `rating` "ломает" порядок `price` внутри индекса.

* При использовании **Индекса А** запрос выполняется полностью по индексу без промежуточной блокировки на сортировку.

## 7. Контрольные вопросы и ответы

1. **Что такое Aggregation Pipeline?**

   Это фреймворк MongoDB для поэтапной обработки и преобразования документов с помощью последовательного конвейера (pipeline), где результат каждого этапа передается на вход следующему.

2. **Для чего используется `$match`?**

   Для фильтрации потока документов по заданным критериям (аналог секции `WHERE` в SQL).

3. **Чем `$project` отличается от обычной фильтрации?**

   `$match` отсекает документы, а `$project` изменяет форму самих документов (выбирает, переименовывает или вычисляет новые поля).

4. **Для чего применяется `$group`?**

   Для объединения документов с одинаковым ключом и расчета агрегированных данных (аналог `GROUP BY` в SQL).

5. **Что означает поле `_id` внутри `$group`?**

   Задает ключ (поле или выражение), по которому производится группировка документов.

6. **Для чего используются `$sum`, `$avg`, `$min` и `$max`?**

   Это аккумуляторы внутри `$group` для подсчета суммы/количества, среднего, минимального и максимального значений по группе.

7. **Что делает `$unwind`?**

   "Разворачивает" массив: создает отдельный документ на каждый элемент массива.

8. **Для чего применяется `$lookup`?**

   Для выполнения левого внешнего соединения (`LEFT OUTER JOIN`) с другой коллекцией той же базы данных.

9. **Что такое индекс MongoDB?**

   Специальная структура данных (B-дерево), хранящая небольшую часть данных коллекции в упорядоченном виде для ускорения поиска документов.

10. **Чем простой индекс отличается от составного?**

    Простой индекс строится по одному полю, составной — по двум и более полям.

11. **Что означает `COLLSCAN`?**

    `Collection Scan` — полное сканирование коллекции из-за отсутствия подходящего индекса.

12. **Что означает `IXSCAN`?**

    `Index Scan` — эффективный поиск по индексному дереву.

13. **Для чего используется `explain("executionStats")`?**

    Для получения подробного отчета о плане и метриках выполнения запроса СУБД.

14. **Что показывают `totalDocsExamined` и `totalKeysExamined`?**

    `totalDocsExamined` — количество прочитанных документов из коллекции. `totalKeysExamined` — количество просканированных ключей в индексе.

15. **Почему индекс может ускорять чтение, но увеличивать стоимость записи?**

    При каждой операции записи, удаления или обновления индексируемого поля MongoDB обязана обновлять не только коллекцию, но и B-дерево индекса.

16. **Почему порядок полей составного индекса важен?**

    Порядок определяет структуру B-дерева. Если порядок полей индекса не соответствует структуре запроса, индекс не сможет использоваться для сортировки или поиска.

17. **Что означает принцип ESR?**

    Правило размещения полей в составном индексе: **E**quality (равенство) ➔ **S**ort (сортировка) ➔ **R**ange (диапазоны).

18. **Почему нельзя оценивать эффективность индекса только по `executionTimeMillis` на маленьком наборе данных?**

    На малой коллекции всё помещается в RAM, и разница в миллисекундах нивелируется. Оценивать нужно соотношение `totalDocsExamined` к `nReturned`.

19. **Как Access Patterns связаны с проектированием индексов?**

    Индексы создаются под конкретные паттерны частых запросов приложения (Access Patterns), а не случайным образом.

20. **В каких случаях индекс может оказаться бесполезным?**

    Если запрос возвращает большую часть коллекции, если селективность поля низкая (например, boolean-поля) или если порядок полей составного индекса нарушает ESR.
